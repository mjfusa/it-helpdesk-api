IT Helpdesk MCP API Documentation

Common Error: Using GET instead of POST

If you're seeing a 404 or 405 error, you are likely trying to access the MCP endpoint using a GET request. The MCP specification requires all operations to use POST requests.

Why Clients Might Incorrectly Use GET

Some MCP clients incorrectly attempt to use GET requests for these reasons:

  • Discovery Attempts: Trying to discover server capabilities before sending JSON-RPC commands
  • REST Misconceptions: Assuming GET is for retrieving data (like listing tools) and POST is only for updates
  • Health Checks: Checking if the endpoint is available without sending a full request
  • Client Library Design: Client libraries may try GET first as a form of probe or handshake

However, the MCP specification is clear that all operations—including initialization, discovery, and tool listing—must use POST requests with JSON-RPC 2.0 payloads.

Correct Usage

The Model Context Protocol (MCP) requires all requests to be made as HTTP POST requests with a JSON-RPC 2.0 payload.

Endpoint

https://ppcjm0mv-5001.usw3.devtunnels.ms/mcp

Headers

Content-Type: application/json
Accept: application/json, text/event-stream

Example Request

{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/list",
    "params": {}
}

Note: All MCP operations are performed via POST requests to the same endpoint. The specific operation is determined by the "method" field in the JSON-RPC payload.

Available Methods

  • tools/list - List all available tools
  • initialize - Initialize the MCP connection
  • tools/call - Call a specific tool (requires name and arguments)

Example Tools

  • GetAllHelpdeskCases
  • GetHelpdeskCase
  • CreateHelpdeskCase
  • UpdateHelpdeskCase
  • DeleteHelpdeskCase
  • SearchHelpdeskCases

Server-Sent Events (SSE) in MCP

Important: The MCP protocol uses Server-Sent Events (SSE) for responses, but this doesn't require a separate route.

Here's how SSE works in MCP:

  1. The client sends a POST request to the single MCP endpoint (/mcp)
  2. The client includes Accept: application/json, text/event-stream in the headers
  3. The server responds using the SSE format, with responses that look like: 
    event: message
data: {"jsonrpc": "2.0", "id": 1, "result": { ... }}
  4. For long-running operations, the server can send multiple SSE messages in a single response

This approach allows for streaming responses and progress updates, without requiring separate endpoints or routes.
